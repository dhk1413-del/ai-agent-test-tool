# AI 机器人问答测试平台

给一个 AI 问答机器人的网址，点一下就跑一轮自动化问答测试；结果在网页上直接看，也能一键下载 Word 测试报告。**一个项目下可以跑多轮测试，自动形成测试记录和跨轮次对比。**

![界面预览](ui-preview.png)

---

## 快速开始

双击 **`start.bat`** 即可。脚本会自动：

1. 检查 Node.js
2. 首次运行时安装依赖
3. 启动本地服务并自动打开浏览器

浏览器会打开 `http://127.0.0.1:3789`。

> 也可以手动启动：在本目录执行 `node server.js`，然后访问上面的地址。

**停止**：在黑色命令行窗口按 `Ctrl+C`，或直接关掉窗口。

---

## 使用流程

1. 点左上角 **「＋ 新建项目」**
2. 填写：
   - **项目名称**：例如「xxx大学图书馆AI馆员」
   - **访问地址**：AI 机器人的完整网址（含 accessToken 等参数）
   - **测试问题**：从下方的分类问题库中勾选（见下一节），也可以在文本框里直接增删
3. 点 **「▶ 开始本轮测试」**，页面会实时显示进度：当前是第几题、正在做什么、已用时间
   - 跑的过程中可以随时 **「⏸ 暂停」**（当前题目跑完后停下）、**「▶ 继续」**、**「■ 停止」**
   - **暂停**不会打断正在生成的回答，也不会产生半截结果；**停止**立即结束本轮，
     已完成题目的结果与截图全部保留，之后照常查看和下载报告
4. 跑完后点该轮次的 **「查看」**：可看到每题的回答全文、耗时、字数、**回答来源**、页面截图
5. 点 **「⬇ 下载本轮 Word 报告」** 得到单轮报告
6. 点项目头部的 **「⬇ 下载项目汇总报告」** 得到包含全部轮次与跨轮次对比的汇总报告
7. 想再测一次？直接再点「▶ 开始本轮测试」，会记为「第 2 轮」，历史轮次全部保留

## Word 报告结构

单轮报告分五节：

| 章节 | 内容 |
|---|---|
| 一、测试概述 | 项目、网址、题目数、成功数等 |
| 二、测试结果总览 | 每题耗时/字数/结果一览 |
| 三、回答来源分布 | 问答库 / 单位知识库 / 其他 各自的题数与占比 |
| 四、逐题问答详情（含页面截图） | **每题的页面截图、问答内容、回答来源放在一起**，一题一页 |
| 五、结果分析 | 成功率、异常题、字数偏短题、来源分布明细 |

### 回答来源与颜色

每题都会标注 **「该答案来自：XXX」**，并按来源着色：

| 来源 | 颜色 | 判定依据 |
|---|---|---|
| 问答库 | 🔵 蓝色 | 页面署名「内容来自：问答库」或过程流显示「问答库召回完成」 |
| 单位知识库 | 🟢 绿色 | 页面署名「内容来自：单位AI知识库」或过程流显示「知识库召回完成」 |
| 其他 | 🔴 红色 | 仅有「该答案由AI大模型生成」，说明**没有检索到任何知识库**，回答无馆方资料支撑 |

> 红色题目建议重点人工复核。汇总报告的结果分析里会直接列出这些题的题号。

## 测试问题库（按业务模块分类）

新建项目和项目配置里都有一个 **测试问题** 模块，题目按图书馆业务模块分好类，勾选即可：

| 模块 | 题量 | 覆盖内容 |
|---|---|---|
| 🏛 图书馆介绍 | 8 | 馆情概况、馆藏规模、特色资源、联系方式、文明公约 |
| 📚 借阅规则 | 17 | 分「开馆时间」「借阅与续借」「超期与赔偿」三个子类 |
| 🔍 馆藏查询 | 8 | 找书、索书号、排架规则、书目检索、状态含义 |
| 🪑 空间服务 | 9 | 座位预约、研修间、电子阅览室、存包柜、研讨室 |
| 💻 电子资源 | 6 | 数据库、校外访问、电子图书、知网下载 |
| 🤝 读者服务 | 8 | 办证、培训讲座、馆际互借、文献传递、荐购 |

共 **56 题**。面板上可以：

- 逐个勾选 / 取消
- 按类 **「全选」「清空」**，或顶部 **「全选全部」「清空全部」**
- 顶部实时显示 **已选 N 题**，每个分类显示 **已选/总数**

**下方文本框始终是唯一数据源**——勾选会自动写入文本框，手动编辑文本框也会反向刷新勾选状态，两者双向同步。所以你既可以整类勾选快速铺开，也可以手工补几条自己的问题。

> 要增删题目，直接改 `lib/question-bank.js` 即可，前端自动生效，无需改代码。

## AI 生成问题（DeepSeek）

分类问题库下面还有一个 **✨ AI 生成问题** 面板：给一个关键词或一句话，自动生成一批测试问题。

- 输入关键词，例如：`座位预约`、`超期罚款`、`电子资源校外访问`
- 选择生成数量（3 / 5 / 8 / 10 题）
- 点「生成」→ 结果带勾选框列出，可逐条取消，确认后点「加入选中的问题」
- 生成时会自动带上**已存在的问题**做去重，避免生成重复题；加入时也会再去重一次

### 首次使用需要配置 API Key

点**左侧边栏底部的「⚙ 系统设置」**（在「浏览器就绪」上方），在弹窗里填写：

- **API Key**：粘贴 DeepSeek 密钥（[获取密钥 ↗](https://platform.deepseek.com/api_keys)）
- **接口地址**：可选，默认 `https://api.deepseek.com`
- **模型**：可选，默认 `deepseek-chat`
- 点 **「测试连通性」** 会先保存再实际调用一次模型，成功/失败结果直接显示在弹窗里
- 点 **「保存」** 生效；已配置后密钥框留空表示不修改，也有「清除密钥」按钮

密钥只保存在本机 `data/settings.json`，界面只回显掩码（如 `sk-abc****3456`），不会外传。

未配置时，「AI 生成问题」面板会提示并提供一个直接跳转到系统设置的按钮。

也可以用环境变量，优先级高于页面配置：

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | API 密钥 |
| `DEEPSEEK_BASE_URL` | 接口地址，默认 `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 模型名，默认 `deepseek-chat` |

> 若检测到环境变量已提供密钥，设置弹窗会提示"环境变量优先级更高，此处保存不生效"。

> 因为走的是 OpenAI 兼容接口，把 `DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL` 换成别的兼容服务（如自建网关、其他厂商）也能用。

## 工作方式

每一题都严格按下面的顺序执行，保证各题互不干扰：

```
点击「新建对话」 → 等待会话重置 → 点输入框 → 主动 focus → 输入问题
   → 校验输入是否生效（不生效则重试）→ 发送 → 校验用户消息是否上屏（失败则换方式重试）
   → 等待回答真正结束 → 抓取回答正文 → 截取页面截图 → 进入下一题
```

引擎会自动探测页面上的 **输入框 / 发送按钮 / 新建对话按钮**，不写死某一个站点，因此对采用同类框架（Coze、超星等）的 AI 问答页面通常都能直接跑通。若某题因页面异常（403、元素消失、超时）失败，会自动重建会话并重试，最多 3 次。

支持两种回答形态：
- **文字型**：完整抓取正文并以文字写入报告
- **卡片型**：页面以组件卡片呈现（如「活动列表」「请点击登录」），自动识别并以页面截图形式存入报告

## 自动化引擎实现要点

针对这类 AI 问答页面的几个坑，`lib/robot.js` 里做了专门处理（都是实测踩出来的）：

| 问题现象 | 根因 | 处理方式 |
|---|---|---|
| 首题输入无效 | 在干净的 ProseMirror 编辑框上按 `Ctrl+A`/`Backspace` 会让其内部状态与 DOM 失步 | 仅在确有残留文本时才清空；输入后校验并按需重新输入 |
| 按钮可点、文案正常，但发送无反应 | 真实鼠标 `mousedown` 会让编辑框失焦，应用读到未同步的状态而忽略本次操作 | 发送优先用 JS 原生 `click()`，其次回车，最后才用坐标点击 |
| 回答只抓到第一行 | 该站点对离屏内容做懒渲染，`innerText` 读不到未渲染部分 | 读取前滚到底触发渲染；`textContent` 更完整时优先采用，并补回换行 |
| 回答被"截断" | 站点会先取回完整答案、再逐字动画渲染，动画中途可能停顿数秒 | 稳定窗口放宽到 10 秒；结束前再强制渲染并复读一次，取更完整的一份 |
| 读到旧内容 | 页面存在多个 frame 时可能读到未更新的那一份 | 逐 frame 读取，取文本最完整的一份 |

如果换到结构差异较大的站点跑不通，优先调整 `lib/robot.js` 顶部的候选选择器列表 `DETECT_SPEC`，以及完成判定阈值 `waitAnswer`。

## 目录结构

```
ai-tester/
├─ start.bat              一键启动
├─ server.js              HTTP 服务与路由
├─ API.md                 接口契约
├─ lib/
│  ├─ config.js           配置（端口、浏览器路径、超时）
│  ├─ chrome.js           受控浏览器生命周期
│  ├─ robot.js            自动化引擎（选择器探测 + 问答 + 卡片识别）
│  ├─ store.js            项目 / 轮次持久化
│  ├─ question-bank.js    分类测试问题库（增删题目改这里）
│  ├─ ai.js               DeepSeek 调用与问题生成
│  └─ report.js           Word 报告生成（单轮 + 汇总）
├─ public/                前端页面（原生 HTML/CSS/JS，零构建）
├─ data/
│  ├─ db.json             项目与轮次索引
│  ├─ settings.json       AI 生成用的 API Key 等配置
│  ├─ runs/<runId>.json   每轮完整数据（含回答原文）
│  └─ shots/<runId>/      每轮每题截图
└─ chrome-profile/        受控浏览器独立配置目录
```

数据全部是本地文件，删除 `data/` 即清空所有测试记录。

## 关于受控浏览器

程序会用一个**独立的 Chrome 配置目录**（`chrome-profile/`）启动浏览器，与你自己日常使用的 Chrome 互不影响，测试过程中你能看到页面在自动操作。

如果提示「浏览器未就绪」，可尝试：

1. 点侧边栏的 **「重启浏览器」** 按钮
2. 关闭所有 Chrome 窗口后重试
3. 确认已安装 Google Chrome（Edge 也可以）
4. 若在受限/沙箱环境中运行，浏览器可能因命名管道权限被拒而无法启动 —— 请在**普通命令行窗口**中重新运行 `start.bat`

## 常见问题

**Q：跑测试时能关掉浏览器窗口吗？**
不能。那是程序控制的浏览器，关掉会导致测试中断。

**Q：为什么某题耗时特别长？**
可能是知识库检索较慢，或该题触发了长文本生成。可调大 `ANSWER_TIMEOUT`。若某题一直卡住，该题会超时后记为「异常/无回答」，不影响后续题目。

**Q：能测非 Coze/超星 的页面吗？**
可以尝试。引擎用的是通用启发式探测，但不同站点的 DOM 差异较大，可能需要调整 `lib/robot.js` 里的候选选择器列表。

**Q：报告里的截图可以单独拿到吗？**
可以。原始截图在 `data/shots/<runId>/q01.png` 等，网页上也逐题展示。
